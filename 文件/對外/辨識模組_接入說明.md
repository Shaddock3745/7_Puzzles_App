# 照片 → JSON 接入（2026-10-20）

本次只接入辨識，不修改選圖、相機、beam search、遊戲版面或場景。

## 檔案與入口

- `Assets/Scripts/GameObject/U2NetContourRecognizer.cs`：實作 `IContourRecognizer`，由 `LevelController.EnsureScanPipeline` 建立。拍照與選檔共用。
- `Assets/Scripts/Recognition/U2NetInputGeometry.cs`：320×320 等比縮放補邊、RGB／ImageNet 正規化、NCHW 與上下方向轉換，遮罩輸出時移除補邊。
- `Assets/Scripts/Recognition/U2NetMaskContour.cs`：沿用協作者 `MaskContourExporter.cs` 的邊界追蹤與簡化，只取最大外框；新增原照片尺寸換算、交叉檢查、點數 20～150 與小物體失敗處理。簡單外形不足 20 點時在邊上補點，不改外形。
- `Assets/Resources/u2netp.onnx`：完整模型，4,574,861 bytes；SHA-256 `309c8469258dda742793dce0ebea8e6dd393174f89934733ecc8b14c76f4ddd8`。模型讀取不需手動拖 Inspector。
- `Packages/manifest.json`：新增 `com.unity.ai.inference` **2.6.1**，沿用辨識分支版本；鎖檔只補必要的新項目，未替換主線既有套件版本。首次開啟需下載開發套件，建置後辨識完全離線。

原本 `U2NetInferenceTest` 的選照片、出題、疊圖按鈕不搬入主線，也不依賴 `MaskOverlayExporter`。

## 回傳契約

輸出 JSON 字串含 `width`、`height`、`pointCount`、`points`，尺寸等於傳入照片；點為左下原點、y 朝上的照片像素座標。保留 normalizedX/Y 供檢查，下游不讀。模型不旋轉或鏡射照片。

協程先 `yield return null`，回呼只在主執行緒執行一次。失敗回 `Failed`，不假裝成功、不退回固定貓咪 JSON。照片不修改、不釋放。模型 Worker 與輸入張量每次使用後釋放；輸出張量由 Worker 擁有，不另行 Dispose。暫存遮罩完成後釋放。

**JSON 直接回傳給既有管線，不會每次寫入專案目錄。** 若要保存樣本，可於除錯時擷取 `ContourJson`。

## 驗證

此更新包附 `U2NetRecognitionTests`，共 10 個案例：橫直正方形補邊、模型左上轉照片左下、原照片尺寸／點數／座標、既有 JSON 讀取器相容性、最大外框／丟棄洞與小物體、空與過小遮罩、常數機率圖。請在 Unity EditMode Test Runner 搜尋並執行。

本環境沒有 Unity 或 C# 編譯器，**這些 Unity 測試尚未執行，也未宣稱 Unity 編譯／推論通過**。已檢查模型大小／SHA-256、安裝腳本語法、首次安裝／重跑／版本衝突拒絕安裝、以及更新不含場景。

測試步驟：在新版工作資料夾開 GameScene → Play → 主畫面「掃描模式」→「從檔案選擇」→ 選已知照片。Console 應出現「U2Net 照片轉 JSON 完成」與後續逼近結果。用至少兩張外形不同的照片確認不是固定樣本；按「照片」確認方向與疊合。再測一次「新拍一張」。

## 本輪限制

準確率與速度尚未評估。這版沿用原模組的同步 `Schedule`／`DownloadToArray`：雖然回呼延後到下一幀，推論與下載結果時仍可能暫停畫面，尚未做到逐幀排程。支援 Compute Shader 時用 GPUCompute，否則用 CPU；Android 入門平板仍需實機測試。模型每次重新建立 Worker，先求流程通，再依量測優化。

若前景面積小於 16 個遮罩像素，或無法簡化成不交叉且不超過 150 點的輪廓，會回失敗。洞不納入外框；不會產生空輪廓。

## 分支交付

預定分支 `feature/image-json-integration`。更新包不會自動 commit 或 push。確認 Unity 編譯、測試與實際掃描後，再逐檔檢查 diff 並從 Mac 推送；雲端分支建立完成後再交給負責人 review。
