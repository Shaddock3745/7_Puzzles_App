## 一、你只要補一個洞

**給你一張照片，回一份輪廓 JSON。** 其他的負責人都做好了：

```
主畫面「掃描模式」→ 選擇視窗 ─┬ 新拍一張（App 裡的相機畫面）──┐
                              └ 從檔案選擇（手機相簿／電腦上是檔案視窗）─┴→ 照片
                                                                  ↓
                                         【你：IContourRecognizer】照片 → 輪廓 JSON
                                                                  ↓
                     進關 ←── 逼近成拼得出來的題目（beam search）←── 讀 JSON
```

| 段 | 狀態 |
|---|---|
| 選擇視窗、拍照、選照片、轉正、縮圖 | ✅ 做好了 |
| **照片 → 輪廓 JSON** | ⬜ **你**。現在 App 裡是假的：不管照片是什麼，都回你 10/14 交的那隻貓 |
| 讀 JSON、逼近成題目、進關 | ✅ 做好了。你那隻貓逼出來的題目 IoU 約 0.81 |
| 照片疊回題目上對照 | ✅ 做好了。你的 JSON 守住第三節的約定，App 就會把**真的照片**疊上去 |

你之前那個「選照片 → 出題」的版本，**取輪廓那一段**就是這裡要的東西；選照片和出題這兩段 App 已經有了，不用帶過來。

## 二、介面

在 `Assets/Scripts/GameObject/ContourScanning.cs`（完整約定寫在它的註解裡）：

```csharp
public interface IContourRecognizer
{
    void Recognize(Texture2D photo, Action<ContourScanResult> onFinished);
}
```

回結果用這兩個（同一支檔案裡的 `ContourScanResult`）：

```csharp
ContourScanResult.Succeeded(json)      // json：第三節格式的字串
ContourScanResult.Failed("沒有找到物體") // 原因會寫進 log
```

### 收到的照片（App 保證）

| | |
|---|---|
| 方向 | **已經轉正**：手機相機的旋轉、相簿照片的 EXIF 方向都處理掉了 |
| 大小 | **長邊不超過 1024 像素**，比例照原照片（例如 1024 × 768、768 × 1024、1024 × 576） |
| 格式 | `Texture2D`，RGBA32，讀得到像素（`isReadable`），沒有 mipmap |
| ⚠️ 像素順序 | `GetPixels32()` 的**第 0 列是照片最下面**（Unity 的習慣）。丟給以「第 0 列在最上面」為準的影像函式庫或模型之前要上下翻 |

### 實作要守的規矩

- ⚠️ **不能在 `Recognize` 裡面當場叫 `onFinished`**，至少等到下一幀（用協程 `yield return null`）
- `onFinished` **只叫一次**、**在主執行緒上叫**（推論可以丟背景執行緒，但結果要轉回主執行緒才叫，Unity 的物件只能在主執行緒碰）
- 只回 `Succeeded` 或 `Failed`，**不要回 `Cancelled`**
- **不要釋放、也不要改那張照片**——之後還要拿去畫照片對照
- 找不到物體、物體太小時回 `Failed` 並寫原因，**不要回一個空的或只有幾個點的輪廓**
- 丟例外不會讓 App 當掉（會被接住、當成失敗），但請盡量自己接住、回清楚的原因

### 骨架

```csharp
using System;
using System.Collections;
using UnityEngine;

public sealed class MyContourRecognizer : IContourRecognizer
{
    private readonly MonoBehaviour coroutineHost;   // 幫忙跑協程，接的時候傳 LevelController 進來

    public MyContourRecognizer(MonoBehaviour coroutineHost) => this.coroutineHost = coroutineHost;

    public void Recognize(Texture2D photo, Action<ContourScanResult> onFinished) =>
        coroutineHost.StartCoroutine(Run(photo, onFinished));

    private IEnumerator Run(Texture2D photo, Action<ContourScanResult> onFinished)
    {
        yield return null;   // 規矩：不能當場回

        // 1. photo.GetPixels32()（記得第 0 列是最下面）→ 前處理 → 模型
        // 2. 機率圖 → 遮罩 → 最大的輪廓 → 簡化
        // 3. 點換算回 photo.width × photo.height、y 朝上 → 組 JSON
        // 失敗：onFinished(ContourScanResult.Failed("原因")); yield break;

        onFinished(ContourScanResult.Succeeded(json));
    }
}
```

## 三、要回的 JSON

**格式照你 10/14 交的那份**：

```json
{
  "width": 1024,
  "height": 768,
  "pointCount": 86,
  "points": [
    { "x": 330.0, "y": 51.0 },
    { "x": 388.0, "y": 51.0 }
  ]
}
```

（示意只列兩個點，實際的 `pointCount` 要等於點的個數。）

| 欄位 | 規則 |
|---|---|
| ⭐ `width`／`height` | **必須等於收到的那張照片的寬高**（`photo.width`／`photo.height`）。模型內部縮成 320 × 320 沒關係，**回來之前把點換算回這張照片的尺寸** |
| `points` | 外框的點，**落在這張照片的像素座標上**，**y 朝上、原點在左下**（你現在就是這樣，請維持——改了不會報錯，只會讓題目上下顛倒） |
| `pointCount` | 等於 `points` 的個數。App 拿它檢查檔案有沒有被截斷 |
| `normalizedX/Y` | 可以留著，App 不讀 |

**品質要求**：

- **一個外形**：多個物體只留最大的那個；**只用外框**，洞丟掉（不要讓外框繞進洞裡再繞出來）
- **不能自己交叉**
- 簡化過，**20 ～ 150 個點**（86 個剛好）
- 不用管繞行方向、不用重複第一點當結尾、大小與位置不用處理（App 會統一）

⚠️ **縮成正方形時建議補邊（letterbox），不要直接壓扁**：直接壓再換算回來，座標雖然對得上，但輪廓已經被壓扁過一次——4:3 的照片會失真，逼近會往錯的形狀靠，而且看不出來。

⚠️ **寬高對不上時 App 不會當掉**，但照片對照會改畫灰底白色的剪影，Console 寫一行警告（兩邊各是多少）。

## 四、怎麼接上去測（在你自己 clone 的那份）

1. 把你的 `.cs` 放進 `Assets/Scripts/GameObject/`，模型檔放進專案（放哪、怎麼讀由你決定）
2. 打開 `Assets/Scripts/GameObject/LevelController.cs`，找 `EnsureScanPipeline`，**只改這一行**：
   ```csharp
   IContourRecognizer recognizer = new SampleFileContourRecognizer(sample != null ? sample.text : null, this);
   ```
   換成
   ```csharp
   IContourRecognizer recognizer = new MyContourRecognizer(this);
   ```
   拍照和選照片兩條路會一起換到
3. 開 `GameScene`，按 Play → 主畫面「掃描模式」→「從檔案選擇」→ 選一張照片（Editor 裡會跳電腦的檔案視窗）
4. **看結果**：

| 看到什麼 | 代表 |
|---|---|
| 進一關，盒子的形狀像照片裡的東西，Console 有一行「IoU …、花了幾秒」 | 整條通了 |
| 按「照片」鈕，**疊上來的是你選的照片，而且物體剛好落在盒子上** | ⭐ 全對（尺寸、座標、y 方向都對） |
| 疊上來的是**灰底白色剪影**，Console 有「照片 W×H … 對不上」 | 你回的 `width`／`height` 不等於照片 |
| 盒子上下顛倒 | y 方向反了 |
| 回到主畫面，Console 有一行警告 | 你回了 `Failed`、JSON 讀不進來（訊息會講哪裡不合法），或逼近不出題目 |

💡 電腦上的 webcam 也可以走「新拍一張」，但「從檔案選擇」比較好重複測同一張照片。

## 五、手機上的限制

| | |
|---|---|
| 裝置 | 決賽用 Android 入門平板（4 GB RAM）。**你手邊沒有，速度由負責人在平板上量**；你只要告訴負責人在電腦上一張照片跑幾秒 |
| 網路 | **完全離線**，整個作品不連網 |
| 時間 | 從按快門到進關希望在 1 分鐘內（決賽展示總共約 6 分鐘）。負責人的逼近在電腦上約 0.7 秒 |
| 模型大小 | 沒有硬上限，但 APK 越大越麻煩，越小越好 |
