## 一、你只要做一件事

**給你一張照片，回一份輪廓 JSON。** 其他的負責人都做好了：

```
主畫面「掃描模式」→ 選擇視窗 ─┬ 新拍一張（App 裡的相機畫面）──┐
                              └ 從檔案選擇（手機相簿）        ─┴→ 照片
                                                                  ↓
                                              【你：照片 → 輪廓 JSON】
                                                                  ↓
                     進關 ←── 逼近成拼得出來的題目（beam search）←── 讀 JSON
```

| 段 | 狀態 |
|---|---|
| 選擇視窗、拍照、選照片、轉正、縮圖 | ✅ 負責人做好了（2026-10-17） |
| **照片 → 輪廓 JSON** | ⬜ **你**。現在 App 裡是假的：不管照片是什麼，都回你 10/14 交的那隻貓 |
| 讀 JSON、逼近成題目、進關 | ✅ 負責人做好了。你那隻貓逼出來的題目 IoU 約 0.81 |
| 照片疊回題目上對照 | ✅ 做好了。⭐ 你的 JSON 守住下面的約定，App 就會把**真的照片**疊上去；守不住會改畫剪影 |

## 二、你會收到的照片（App 保證）

| | |
|---|---|
| 方向 | **已經轉正**：手機相機的旋轉、相簿照片的 EXIF 方向都處理掉了。你不用管方向 |
| 大小 | **長邊不超過 1024 像素**，比例照原照片（例如 1024 × 768、768 × 1024、1024 × 576） |
| 格式 | Unity 的 `Texture2D`，RGBA32，讀得到像素。⚠️ 像素的**第 0 列是最下面**（Unity 的習慣，跟一般影像函式庫相反） |

拍攝條件 App 不控制：可能是任何背景、任何光線。決賽現場會準備單色背景板。

## 三、你要回的 JSON

**格式照你 10/14 交的那份就好**，不用改成舊文件裡的 `rings`：

```json
{
  "width": 1024,
  "height": 768,
  "pointCount": 86,
  "points": [
    { "x": 330.0, "y": 51.0 },
    { "x": 388.0, "y": 51.0 }
  ]
}
```

（示意只列兩個點，實際的 `pointCount` 要等於點的個數。）

| 欄位 | 規則 |
|---|---|
| ⭐ `width`／`height` | **必須等於收到的那張照片的寬高**。你的模型內部縮成 320 × 320 沒關係，**回來之前把點換算回這張照片的尺寸** |
| `points` | 外框的點，**落在這張照片的像素座標上**，**y 朝上、原點在左下**（你現在就是這樣，請維持——改了不會報錯，只會讓題目上下顛倒） |
| `pointCount` | 等於 `points` 的個數。App 拿它檢查檔案有沒有被截斷 |
| `normalizedX/Y` | 可以留著，App 不讀 |

**品質要求**（跟之前一樣）：

- **一個外形**：多個物體只留最大的那個；目前**只用外框**，洞可以丟掉
- **不能自己交叉**
- 簡化過，**20 ～ 150 個點**（86 個剛好）
- 不用管繞行方向、不用重複第一點當結尾、大小與位置不用處理

⚠️ **縮放建議用補邊（letterbox），不要直接壓成正方形**：直接壓再換算回來，座標雖然對得上，但輪廓的形狀已經被壓扁過一次——4:3 的照片會失真，逼近會往錯的形狀靠，而且看不出來。

**找不到物體時**：回失敗並附原因（例如「沒有找到物體」「物體太小」），App 會回主畫面。不要回一個空的或只有幾個點的輪廓。

## 四、⭐ 交付形式：二選一（請先回覆選哪個）

| | **A：ONNX ＋ 規格**（C# 由負責人寫） | **B：你直接寫 C#** |
|---|---|---|
| 你交什麼 | ① ONNX 模型檔 ② **前後處理規格**（見下）③ **測試向量**（見下） | ① 一支 `.cs`，實作 `IContourRecognizer` ② 模型檔 ③ 用到的 Unity 套件與版本 |
| 負責人做什麼 | 裝 Unity 的推論套件（Inference Engine，前身叫 Sentis），照你的規格寫前處理、推論、後處理 | 把檔案放進專案、接上一行 |
| 你需要什麼 | Python 那邊就夠 | 你自己要有 Unity 6000.3 ＋推論套件，能在 Unity 裡跑 |
| ⚠️ 風險 | **後處理要在 C# 重寫**：「機率圖 → 遮罩 → 找最大的輪廓 → 簡化」在 Python 是 OpenCV 幾行，Unity 裡沒有 OpenCV，負責人要自己寫。規格寫不清楚就會跟你的結果不一樣——所以**測試向量一定要有** | 你要守 Unity 的規矩（見下），出錯時兩邊都比較難查 |

### 選 A 的話：規格要寫到「照著做就能重現」

| 段 | 要寫清楚的 |
|---|---|
| 前處理 | 輸入尺寸；**補邊還是直接縮**（補邊的話補什麼顏色、置中還是靠角）；RGB 還是 BGR；正規化（減多少、除多少，每個通道各是多少）；張量排法（NCHW 還是 NHWC） |
| 模型 | ONNX 檔、**opset 版本**、輸入輸出張量的名字與形狀；有好幾個輸出的話用哪一個（U²-Net 有 d0 ～ d6）；輸出要不要再過 sigmoid |
| 後處理 | 閾值多少；有沒有做開閉運算（核多大）；怎麼挑出最大的物體；找輪廓用什麼規則；簡化用什麼方法、參數多少（例如 Douglas–Peucker 的 ε）；**怎麼換算回原照片座標**（補邊的話要扣掉邊） |

**測試向量**：3 張照片，每張附上**你的程式每一段的中間結果**——縮好的輸入圖、模型輸出的機率圖（存成 PNG 或 `.npy`）、二值化後的遮罩、最後的 JSON。
負責人寫完 C# 之後一段一段對，哪一段開始不一樣就知道錯在哪。**沒有測試向量的話，對不上時只能猜。**

### 選 B 的話：Unity 的規矩

介面在 `Assets/Scripts/GameObject/ContourScanning.cs` 的 `IContourRecognizer`，約定的完整版寫在它的註解裡。重點：

- 只有一個方法：`Recognize(Texture2D photo, Action<ContourScanResult> onFinished)`
- **不能在 `Recognize` 裡面當場叫回呼**，至少等到下一幀（用協程）
- 回呼**只叫一次**、**在主執行緒上叫**（背景執行緒跑推論可以，但結果要轉回主執行緒才叫）
- 成功回 `ContourScanResult.Succeeded(json)`，失敗回 `ContourScanResult.Failed(原因)`；**不要回 `Cancelled`**
- **不要釋放、也不要改那張照片**——之後還要拿去畫照片對照
- 要加推論套件以外的東西（外掛、DLL）先問負責人

## 六、怎麼確認自己做對了

1. **尺寸**：JSON 的 `width`／`height` 跟你收到的照片一樣
2. **座標**：把點畫回原照片上（記得 y 朝上：畫的時候 `y_畫面 = height − y`），要剛好描在物體邊上
3. **在 App 裡看**：接上之後玩一題掃描題，按「照片」鈕——**疊上來的是你拍的照片、而且物體剛好落在題目的框上**，就是全對了。
   疊上來的是灰底白色剪影的話，代表尺寸對不上（Console 會有一行警告寫兩邊各是多少）
